# 仕様書

アプリの「何を・どう動かすか」を書く。AIは作業の前に必ずここを読む。

## 目的

釣り人・海辺の撮影者向けに、地点ごとの潮と日の出入りを読み解いて最適な時合いを予告し、有料では複数地点の比較と通知が使える潮汐暦サービス（元のメモ：会員登録して月額の有料プランで使う、ありきたりでない Web サービス（中身はおまかせ））

## 前提

- 使う人・使う場面（デザイン担当の分析。推定を含む）：
  - 磯・堤防・サーフの釣り人が、前の晩にスマホで「明日はどの地点へ、何時に入るか」を決めるために開く
  - 朝焼け・干潟の反射を狙う海辺の撮影者が、薄明の時間と潮の低さが重なる朝を探すために使う
  - 無料は「いつもの一地点」の今日と明日。有料（月480円）は複数地点の比較・時合いと干潮の通知・30日先までの暦
  - 潮位は気象庁の調和定数（主要4分潮）から推算した値（出典は `src/lib/spots.ts` の冒頭）。6地点は城ヶ島・江の島・洲崎・伊良湖岬・大浦・串本。海に出る判断は現地の情報と合わせて行う前提
- 技術：Next.js（App Router）＋TypeScript、テストはVitest。会員登録・ログインは Supabase、月額の有料プランは Stripe（`docs/billing.md`）

## 無料と有料

- 無料でできること：地点を1つ登録（`MAX_SPOTS_FREE`）／登録した地点の今日と明日の潮汐曲線・満潮と干潮・日の出入り・時合い
- 有料プラン（月額）でできること：地点を12地点まで登録（`MAX_SPOTS_PRO`）／登録した地点の「明日」の時合いを強い順に並べた比較の表。通知の設定と、メールでの通知の送信（下の「通知の設定」）。30日先までの暦と、撮影の「青い時間」×潮の高さ（下の「わたしの暦」）
- 上限の数は `src/lib/saved-spots.ts` の定数で持ち、`PLAN_ROWS` の「保存できる地点」と同じ値にする
- トップ（`/`）では、ログインしていなくても無料の範囲（今日・明日・比較の1位）を見せ、有料の範囲は「鍵つきの行・欄」で示す（下の「トップ」）。鍵つきの行・欄は押すと `/pricing` に行き、中身はサーバーで作らない

### 料金（`/pricing`）

- 見出し「料金」と、無料と有料の違いの表だけ。表の1行目に値段（無料 0円・有料 月 480円（税込）。`PRICE_YEN`）、続けて `PLAN_ROWS` の行、最後の行に申し込みのボタン（無料はログイン・アカウントへ、有料は `/api/stripe/checkout`。有料の人には「いまのプランを見る」）

## 画面

### わたしの暦（`/mine`）

- ログインしていなければ `/login?next=/mine` へ。ヘッダーの「わたしの暦」（ログイン済みの人だけ）と、`/account` の「わたしの暦へ」から来る
- 登録した地点は `public.saved_spots` 表（`supabase/migrations/0002_saved_spots.sql`、RLS で自分の行だけ）に保存する。選べる地点は `SPOTS` の6地点
- 登録欄：未登録の地点から1つ選んで「地点を追加」。登録済みの一覧には「削除」ボタンがあり、いつでも消せる
- 追加・削除は Server Action（`src/app/mine/actions.ts`）。最初に `getViewer()` で `user` を確かめ、追加では `checkAdd`（存在する地点か・二重でないか・上限を超えないか。上限は `pro` を見る）をサーバーで判定する。断ったら `/mine?e=理由` に戻し、画面に理由を出す（`limit`・`duplicate`・`unknown`・`fail`）
- 無料：登録は1地点まで。その地点の今日と明日の潮汐曲線・満潮と干潮・日の出入り・時合いを出す。2地点目を足せない状態では、追加欄を隠し、有料プラン（`/pricing`）の案内を出す。地点を変えたいときは、削除してから追加する。比較の表は出さない
- 有料：12地点まで。登録した地点の「明日」の時合いを、いちばん強い時合いの強さの順に並べた比較の表を出す（トップの「地点の比較」と同じ部品 `CompareTable`。`domain` で潮位の物差しをそろえる）
- 有料が切れて登録が1つより多く残った人：削除はできるが追加はできない。登録済みの地点は消さず、無料の表示では先に登録した1地点だけ出す（`visibleSpotIds`）
- 先読みと撮影（`src/lib/forecast.ts`。純粋な関数。有料かどうかはページがサーバーで `getViewer().pro` から渡す）
  - 見られる日：無料は今日と明日（`FORECAST_DAYS_FREE`＝1）。有料は今日から30日先まで（`FORECAST_DAYS_PRO`＝30。今日と30日先を含む31日）
  - 30日先までの暦（有料のみ）：登録した地点のうち1つを選んで出す。選ぶのは `?spot=<id>`（登録済みの地点だけ。無い・不明・登録外のときは先に登録した地点）。日ごとに、日付・潮名・いちばん強い時合い（時刻と理由）・強さを並べる（`calendarRows`）。時合いが無い日は「—」
  - 撮影の「青い時間」×潮の高さ：朝の青い時間（薄明の始まりから日の出の20分後）の潮が、その日の幅の下から30%以下（`mirror`。干潟や潮だまりが空を映す）の朝を探す（`photoMornings`）。有料は選んだ地点の30日先までの該当する朝を日付順に並べる（日付・青い時間の時刻・潮の高さ○%）。該当する朝が無いときは「この30日には、潮が低い朝がありません。」と出す。無料は今日の朝と夕の青い時間と潮の高さだけを出す（`photoToday`。探すことはできない）
  - 無料には30日先の暦を出さず、有料プラン（`/pricing`）の案内に「30日先までの暦と、撮影の青い時間×潮の高さ」を書き添える
- 潮位には「推算値」と書き添える。環境変数が無いとき（`authEnabled()` が偽）は、ログインできないので `/login` へ移る

### 通知の設定（`/account` の「通知」の節。有料のみ）

- 種類は2つ。**時合いの通知**（前の晩21時と、時合い開始の90分前をまとめて1つの on/off）と、**干潮の通知**（翌朝の干潮が、決めたしきい値を下回るとき）。初期はどちらも off。干潮のしきい値は初期 30cm、0〜200 の整数（cm）
- 設定は `public.notification_settings` 表（`supabase/migrations/0003_notification_settings.sql`、RLS で自分の行だけ）に1人1行で持つ。保存は Server Action（`src/app/account/actions.ts`）。最初に `getViewer()` で `user` と `pro` をサーバーで確かめ、無料・未ログインは断る（未ログインは `/login`、無料は `/account?n=pro`）。しきい値は `parseThreshold`（0〜200 の整数以外は保存せず `/account?n=invalid`）。保存できたら `/account?n=saved`、DB の失敗は `n=fail`
- 無料には設定フォームを出さず、有料プラン（`/pricing`）の案内を出す。有料が切れた人の保存済みの設定は消さない（画面には出さない）
- 送る時刻の決め方（`src/lib/notifications.ts` の `planNotifications(spot, date, settings, now)`。純粋な関数。時刻はすべて日本時間）
  - `date`＝知らせる日（「明日」）の JST 0時。通知の対象の地点は呼ぶ側が渡す（送信は下の「送信の決まり」）
  - 時合いの通知：`jiaiWindows` の時合いについて、前の晩21時（`date` の前日21:00）にいちばん強い時合いを1通、時合いごとに開始の90分前（日付をまたぐことがある）に1通
  - 干潮の通知：`date` の 0時〜正午の干潮（`extremes`）の潮位がしきい値を**下回る**（同じ値は含まない）とき、前の晩21時に1通
  - 設定が off の種類は返さない。送る時刻が `now` より前の物も返さない。結果は送る時刻の早い順
- 送信の決まり（メールだけ。`src/lib/notify-run.ts`・`src/lib/mailer.ts`・`src/lib/notification-mail.ts`）
  - 定期実行：`vercel.json` の cron が毎日 21:00（日本時間。cron は UTC で `0 12 * * *`）に `GET /api/notify` を呼ぶ。Vercel の無料プラン（Hobby）は cron が1日1回までで、15 分おきにすると公開そのものが断られるため。いまは前の晩21時の通知だけが送られ、時合いの90分前の通知は送られない（送るには、15 分おきに呼ぶ別の仕組みが要る）。`Authorization: Bearer ${CRON_SECRET}` が合わなければ 401。`CRON_SECRET`・`EMAIL_API_KEY`・`EMAIL_FROM`・Supabase の鍵のどれかが無いときは、何もせず 200（`{ skipped: true }`）で終わる
  - 対象：`notification_settings` で on の種類がある会員のうち、**いま有料**の会員（`subscriptions` 表と `isPro`）。無料に戻った会員には送らない（保存済みの設定は消さない）。地点は会員が `saved_spots` に登録した全地点
  - 選び方：今日と明日（JST 0時）それぞれで `planNotifications` を呼び、送る時刻が「前回の実行から今回まで」（今回の 15 分前以上・今回より前）の物だけ送る。90 分前の通知は日付をまたぐことがあるので、今日の分も見る
  - 二重送信の防止：送る前に `public.notification_log` 表（`supabase/migrations/0004_notification_log.sql`）へ `(user_id, spot_id, kind, send_at)` を書く。一意制約に当たった（もう書いてある）物は送らない。送るのに失敗したら記録を消す。この表は `supabaseAdmin()` だけが読み書きする（RLS 有効、一般の policy なし）
  - 宛先は会員のメールアドレス（`auth.users`）。配信は Resend の HTTP API（`EMAIL_API_KEY`・`EMAIL_FROM`）。件名と本文は日本語で、潮位には「推算値」と書き添える

### トップ（`/`）

トップは宣伝のページではなく、開いてすぐ選んでいる地点の暦が読める「道具」。上から次の順に並べる。宣伝の見出し・写真・料金の節は置かない（料金は上の帯と足もとの `/pricing` へのリンクだけ）。

1. **上の帯**：しるし（`/` へ）・地点の切り替え・日付の切り替え・右にログイン（ログイン中は「わたしの暦」）
2. **選んだ日の暦**（最初の画面に必ず入る。390px でも 1440px でも）：見出し「地点名 日付 潮名」（例「城ヶ島 11月5日（木） 長潮」）、満潮・干潮・日の出・日の入り・月齢の並び（今日を選んでいるときは「いまの潮」も）、潮汐曲線（`TideChart`）、時合いの帯（例「時合い 5:50–8:40 上げ潮 × 朝まずめ 強」）。曲線の札（満潮・干潮／時合い／いま）は、640px 以下では重ならないよう置く（満潮・干潮は常に出し、「いま」の札は干潮の札と近ければ反対側か省略、「時合い」の札は他の札と線を避けてずらす。`mobileTags`）。日付の切り替えは 390px でも切れずに 6つが収まる。曲線の下に「暦の読み方」の折りたたみ（`<details>`）と、「※ 推算値（潮位は気象庁の調和定数から推算）…」の注記
3. **明日以降**：明日〜5日先の5日分の小さな曲線を横に並べる
4. **地点の比較**：選んだ日の、全地点（`SPOTS`）のいちばん強い時合いを強い順に並べた表

#### 地点の切り替え（#3 の検索）

- 上の帯の「地点」を開く（`<details>`）と、検索欄（`?q=`）と地点の一覧が出る。地点名か地域を入れて「探す」を押すと、`SPOTS`（見本の6地点）を `name` / `area` の部分一致で絞る（`searchSpots`）。前後の空白は無視。ひらがな・全角半角の違いは扱わない。検索欄は JavaScript なしの GET フォーム。検索語があるとき（`q` が空でない）は、開いた状態で出す
- 空のとき（初めて開いたとき）は全地点を出す。0件のときは「「○○」に合う地点は見つかりませんでした。…」と出す
- 一覧の地点を選ぶと URL が `?spot=<id>` になり、トップの暦がその地点に切り替わる。検索語 `q` と日付 `d` は選んだあとも保つ
- `?spot` が無い・不明な id のときは城ヶ島（`spotById` の既定）
- 選んだ地点は URL に持つだけで保存しない（保存は会員の画面）

#### 日付の切り替え（`?d=`）

- `?d=` は今日からの日数（`0`〜`5` の1桁の整数）。既定は今日（`0`）。上の帯に「今日」「明日」「7日」…「10日」（2日先からは日にちだけ）を並べる（`dayChips`）
- 無料は `0`（今日）と `1`（明日）だけ選べる（`HOME_DAYS_FREE`＝1）。有料（`getViewer().pro`）は `5` まで（`HOME_DAYS_PRO`＝5）
- 解釈は `parseDayOffset(raw, pro)`（`src/lib/home.ts`）。無い・数字でない・範囲の外・無料で `2` 以上のときは今日（`0`）に戻す
- 選べない日（鍵つきの日。`isDayLocked`）は、鍵の印をつけて薄く出し、押すと `/pricing`
- 地点・日付・検索語のリンクは `homeHref` で作る（既定の値は URL に入れない）

#### 明日以降

- 明日〜5日先の5枚。1枚＝日付・潮名・小さな曲線（`TideChart` の札なし・目盛りなし。5枚の潮位の物差しは `domain` でそろえる）・いちばん強い時合いの時刻と強さの言葉。押すと `?d=` でその日を選ぶ（選んでいる日は印をつける）
- 無料は明日の1枚だけ中身を出す。2日先からは鍵つき：日付と鍵の印だけの薄い枠にし、押すと `/pricing`。**鍵つきの日の曲線・時合い・潮名は、サーバーで作らず HTML にも入れない**（`previewDays` の `locked`）
- 有料（`getViewer().pro`）は5枚とも中身を出す

#### 地点の比較

- 選んだ日の全地点を、いちばん強い時合いの強さの順に並べる（`compareRows`。時合いが無い地点は最後）。1行＝順位・地点名と地域・潮名・小さな曲線（`domain` でそろえる）・いちばん強い時合いの時刻と理由・強さの言葉。1位の行に印をつける
- 無料は1位の1行だけ見せ、残りは鍵つきの行にする：順位と「有料プランで比べられます」と鍵の印だけで、地点名・曲線・時合いはサーバーで作らず HTML に入れない。鍵つきの行は押すと `/pricing`
- 有料は全地点の行を出す。有料の判定はサーバーで `getViewer().pro`

#### 時合いの強さの言葉

- 強さ（0〜100）は数字ではなく言葉で出す（`strengthOf`。`src/lib/strength.ts`）：70 以上「強」、55 以上「並」、それより下「弱」。時合いの帯と曲線の中の時合いの塗りは、強いほど濃くする
- 潮位には「推算値」と書き添え、出典（気象庁の調和定数から推算）を近くに書く
